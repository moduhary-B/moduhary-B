## API

### 1. [API автомобильных аукционов](https://github.com/moduhary-B/car-auction-api)

**Задача:** спарсить и объединить данные автомобилей с разных аукционов в одном API.

- Спроектировал FastAPI-сервис, который объединяет три разных источника данных через независимые адаптеры и общую модель.
- Реализовал хранение в SQLite: архив проданных лотов, снимки каталогов, аккаунты, прокси, телеметрия и история служебных операций.
- Собрал систему аккаунтов и прокси: шифрование учётных данных, состояния аккаунтов, привязка к прокси, ротация, сохранение сессий и автоматическое переключение после ошибок.
- Добавил Redis-кеш, защиту от одновременных одинаковых запросов, резервные снимки данных, API-ключи, ограничение запросов, административные методы и метрики.

### 2. [API отзывов из 2ГИС и Яндекс Карт](https://github.com/moduhary-B/rew-api)

**Задача:** централизованно собирать отзывы для нескольких клиентских сайтов.

- Спроектировал многопользовательский backend на FastAPI и PostgreSQL: проекты, организации, источники, отзывы, медиа и история синхронизаций.
- Реализовал изоляцию данных клиентов на уровне запросов и отдельные Bearer-ключи, привязанные к конкретному проекту.
- Вынес 2ГИС и Яндекс Карты в независимые адаптеры; новый источник подключается без изменения основной бизнес-логики.
- Сделал обновление отзывов, фоновые синхронизации, retry/backoff, журнал ошибок и миграции Alembic.
- Использовал Python, SQLAlchemy, Playwright, Docker, Pytest и Ruff.

### 3. [Lindy2API](https://github.com/moduhary-B/lindy2api)

**Задача:** подключить Lindy.ai к OpenAI-совместимым клиентам с сохранением потоковых ответов и продолжением разговоров после перезапуска.

- Исследовал внутренний протокол Lindy.ai и реализовал OpenAI-совместимый HTTP-прокси на Node.js 22.
- Связал обычные API-запросы с GraphQL и SocketCluster/WebSocket-событиями веб-приложения.
- Реализовал обычные и потоковые ответы, heartbeat, таймауты и преобразование событий в формат Server-Sent Events.
- Создал SQLite-хранилище соответствий между разговорами клиента и задачами Lindy с восстановлением после перезапуска.
- Добавил адаптер tools/tool_calls и административные методы; сервис написан без внешних npm-зависимостей.

### 4. [Universal Downloader API](https://github.com/moduhary-B/universal-downloader)

**Задача:** выполнять тяжёлые загрузки в фоне и не позволять публичному сервису исчерпать очередь, процессор, время или место на диске.

- Разработал асинхронный FastAPI-сервис с очередью фоновых задач поверх yt-dlp, spotDL и FFmpeg.
- Отделил HTTP API от тяжёлой обработки: запрос создаёт задачу, а состояние и результат запрашиваются отдельно.
- Реализовал ограничение параллельных задач, времени выполнения, размера, длительности и доступного места на диске.
- Добавил белый список доменов, ограничение запросов по IP, запрет плейлистов и автоматическую очистку временных файлов.
- Спроектировал API, очередь, единый интерфейс внешних программ и обработку их ошибок.

## Автоматизация

### 1. [Расширение для браузера Coda Temp Mail](https://github.com/moduhary-B/coda-tempmail-extension)

**Задача:** перенести работу с временной почтой в расширение Firefox и безопасно отображать содержимое входящих HTML-писем.

- Восстановил Firefox-расширение на JavaScript поверх модулей API, хранения и обработки данных.
- Реализовал отдельный слой запросов к backend, классификацию сетевых и HTTP-ошибок и локальное состояние через browser.storage.local.
- Добавил очистку HTML через DOMPurify и блокировку внешних изображений, чтобы письмо не могло выполнить код или незаметно загрузить tracking pixel.
- Разделил интерфейс, API, storage, sanitization и локализацию на независимые модули.
- Подготовил безопасную версию и проверил её официальным Firefox linter.

### 2. Сбор компаний VL.ru и автоматизация обращений

**Задача:** находить компании нужных направлений без собственного сайта и автоматизировать первичное обращение по указанным ими контактам.

- Первый независимый модуль парсил каталог компаний VL.ru, проверял направление и наличие сайта, извлекал данные карточки и контакты.
- Подходящие компании сохранялись в базе данных; сборщик отвечал только за получение и обновление информации, а не за отправку сообщений.
- Второй модуль запускался по отдельному расписанию, выбирал записи из базы, формировал сообщения и отправлял их через WhatsApp или Telegram.
- Для исходящих обращений использовались несколько аккаунтов, прокси и распределение отправок, чтобы каналы и сессии не зависели от одного аккаунта.

### 3. [FreeModel Panel](https://github.com/moduhary-B/freemodel-panel)

**Задача:** контролировать состояние и лимиты нескольких аккаунтов в одной внутренней панели без постоянных лишних запросов к внешнему сервису.

- Разработал внутренний HTTP-сервис на чистом Node.js без сторонних библиотек.
- Реализовал JSON API для CRUD-операций с аккаунтами и обновления их состояния по cookie.
- Добавил последовательный фоновый polling и presence-механику: запросы выполняются только пока панель используется.
- Настроил хранение состояния в подключаемом Docker volume и работу сервиса только во внутренней Docker-сети.
- Написал backend, API, хранение, планировщик обновлений и интеграцию с внешней панелью.

### 4. [Система многоголосой озвучки книг через LLM и TTS](https://github.com/moduhary-B/audiobook-pipeline)

**Задача:** автоматизировать многоголосую озвучку художественных книг с сохранением голосов для персонажей, поддержкой эмоций и контекста.

- Спроектировал модульный Python-конвейер с независимыми интерфейсами LLM, TTS, предобработки, валидации и сборки.
- Реализовал разметку текста в структурированный JSON, проверку схемы и character_id и сохранение контекста между главами.
- Добавил реестр персонажей и голосов, транскрипцию референсов через Whisper и синтез через Qwen3-TTS.
- Реализовал повторную генерацию отдельных неудачных реплик вместо полного перезапуска.
- Собрал финальный этап на FFmpeg с управлением паузами, скоростью, высотой и громкостью.

### 5. Система поиска спредов между CEX/DEX-биржами

**Задача:** находить реальные арбитражные возможности между 20 популярными криптобиржами, а не просто сравнивать текущие цены.

- Изучил API каждой биржи и написал асинхронный сканер на Python для одновременного сбора и обработки рыночных данных.
- Для каждой торговой пары анализировал стакан, ликвидность, доступный объём, комиссии, активность и время обновления данных.
- Проверял доступность ввода и вывода монеты и совместимость используемых сетей между биржами.
- Рассчитывал фактическую прибыль с учётом глубины стакана и всех расходов, отбрасывая спреды, которые невозможно реализовать.
- Подходящие под заданные критерии возможности автоматически отправлялись в Telegram-бота.

## VPN и Proxy

### 1. [Десктоп-клиент для работы с прокси](https://github.com/moduhary-B/voxy)

**Задача:** управлять несколькими прокси в Windows и направлять через них отдельные приложения и домены, не переключая весь трафик компьютера.

- Разработал Windows-приложение с frontend на React 19 и системным backend на Rust/Tauri 2.
- Реализовал генерацию конфигурации sing-box для SOCKS5, Shadowsocks и VLESS и управление его процессом.
- Добавил маршрутизацию по доменам и exe-процессам в режимах whitelist/blacklist и отдельные конфигурации профилей.
- Реализовал хранение профилей с шифрованием AES-256-GCM, проверку соединения и корректное завершение дочернего процесса.
- Подготовил CLI-режим и production-сборку Windows; проект проходит TypeScript build и ESLint.

### 2. [Распределённая VPN-инфраструктура](https://github.com/moduhary-B/distributed-vpn-platform)

**Задача:** объединить множество VPN-нод в одну управляемую систему, где пользователь подключается одной кнопкой, а выбор сервера, выдача ключа и маршрутизация выполняются автоматически.

- Спроектировал три уровня: центральный FastAPI-менеджер, VPN-ноды на Docker и Xray VLESS-Reality и Windows-клиент на Python с pywebview.
- Создал SQLite WAL-базу для клиентов, подписок, серверов, UUID-ключей, маршрутов и телеметрии; добавил атомарную выдачу, HWID-привязку, heartbeat и возврат зависших ключей в пул.
- Менеджер исключает перегруженные ноды, сортирует остальные через локальную GeoLite2, а клиент параллельно проверяет семь ближайших по TCP и при ошибке пробует следующую.
- Написал SSH-провижинер на Paramiko: он поднимает новую ноду из чистого Ubuntu VDS, устанавливает Docker/Amnezia Xray, генерирует 500 UUID, настраивает firewall и телеметрию; состояние видно в SPA-панели с картой.
- Реализовал в Windows-клиенте Xray, session cache, split routing и управление системным прокси; менеджер разворачивается через Docker Compose и Nginx с ограничением запросов.

**Задача:** остановить опасный вызов инструмента до его выполнения AI-клиентом и не передавать настоящий ключ LLM API на пользовательские устройства.

- Разработал reverse proxy на Go между AI-клиентом и Anthropic-совместимым LLM API.
- Реализовал авторизацию устройств отдельными токенами и хранение настоящего upstream-ключа только на сервере.
- Написал потоковый SSE-парсер, который собирает tool_use и JSON-аргументы из нескольких разорванных фрагментов ответа.
- Добавил RE2-правила, IOC-блоклист, режимы monitor/block, горячую перезагрузку ключа и уведомления в Telegram.
- Подготовил Docker-развёртывание.

### 2. [Переносимая инфраструктура VPS](https://github.com/moduhary-B/portable-vps-infra)

**Задача:** сделать серверную инфраструктуру воспроизводимой, переносимой между провайдерами и проверяемо восстанавливаемой из резервной копии.

- Описал серверную инфраструктуру через Docker Compose и Traefik вместо набора ручных команд на конкретном VPS.
- Реализовал snapshot и restore для PostgreSQL, именованных Docker volumes, registry с образами и дополнительных каталогов.
- Настроил restic-бэкапы в S3-совместимое хранилище и сценарии bootstrap/migrate для переноса на чистый сервер.
- Использовал Cloudflare Tunnel, SOPS и age, чтобы отделить маршрутизацию и секреты от исходного кода.
- Подготовил Makefile, Bash-сценарии и шаблоны для web-сервисов, worker-процессов и Telegram-ботов.

### 3. [Быстрый экспорт сообщений Telegram](https://github.com/moduhary-B/tg-fast-exporter-bot)
